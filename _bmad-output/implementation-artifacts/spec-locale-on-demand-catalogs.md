## Current loading and consumer assumptions

- `src/platform/i18n/locales.ts` imports six non-English JSON catalogs eagerly; English is reconstructed from `messages.ts` defaults and tested against `catalogs/en-US.json`. Its `catalogs` object is therefore transitively pulled into `main.tsx` through `MiaIntlProvider.tsx`. `messages.ts` descriptors must remain eager for the many entry and lazy-route consumers; their English defaults do not authorize substituting English for a missing selected catalog.
- `src/main.tsx` strips invitation/reset fragments as its first application instructions, resolves stored locale before browser-language negotiation, applies `html.lang` and text size, then mounts the app. Do not start catalog loading, other optional imports, a router or API work before the synchronous fragment capture/removal. `index.html` currently defaults to English title/lang before bootstrap; initial React content must never show it as a substitute for a non-English selection.
- `MiaIntlProvider` currently changes `html.lang`, preference storage, React locale, Intl messages and announcement in one synchronous event. `SignedOutEntryRoute` has the only current `changeLocale` caller (native selector). The invitation form displays localized option names but does not switch the interface. `App.test.tsx` asserts same-event heading/title/announcement/focus/storage; its provider fixtures and `tutoringSession.test.tsx` assume the complete synchronous `catalogs` object. Keep synchronous *render* with the loaded active catalog by injecting it into the provider; adapt fixtures to supply an explicitly loaded catalog rather than reintroducing eager production imports.
- `scripts/message-catalogs.ts` rewrites the six JSON modules into compact value tables at build time; `es-AR` imports the `es-ES` base and `pt-BR` the `pt-PT` base, sharing `catalogMessageIds` from the packed descriptors. `vite.config.ts` enables that plugin and emits `dist/.vite/manifest.json`. Literal `import()` paths/`import.meta.glob` in Vite 8 form dynamic chunks, while static imports remain in the entry's static closure; a regional dynamic chunk can depend on a base chunk. Inspect the **built manifest and network**, not just source syntax: avoid an eager import or modulepreload that pulls every locale back into first paint.
- `npm run check:i18n` (`scripts/check-i18n-catalogs.mjs`) extracts `messages.ts` and checks all seven canonical JSON files for exact IDs, nonempty strings, matching ICU arguments and compilability. `scripts/message-catalogs.test.ts` checks packed descriptor/catalog value parity. Keep both checks. `scripts/check-bundle-size.mjs` currently totals gzip over entry/static imports only; extend its measurement to include the single selected catalog's dynamic closure on each of seven cold initial loads, without counting six unrequested catalogs. Fail if any initial locale exceeds 260,000 bytes; separately assert the entry/static closure contains no catalog chunk. Do not silently weaken the budget.

## Delivery design and acceptance

1. **Bootstrap:** Keep `resolveInitialLocale` and negotiation precedence unchanged. After synchronous fragment capture and other existing pre-router guards, request **only the selected locale's** static, same-origin catalog with an explicit seven-key dynamic-import loader. Wait before `createRoot`/session discovery; on success supply that catalog to `MiaIntlProvider` and render the first React tree with matching `html.lang`, title, formatted strings, dates and statuses. No partial tree, key flash, English fallback or speculative protected fetch. English uses its real `en-US.json` on this path, even though descriptor defaults remain eagerly available. Successful first paint is synchronous **with respect to the first React render**, not a claim that an uncached network request is instantaneous; record cold FFR-951/952 impact.
2. **Loaded switching:** Keep a page-local in-memory map of successful catalogs and single-flight loads (not browser storage or a protected-data cache). When a target is cached, commit language/Intl catalog, preference, document title/content and announcement atomically on that activation, preserving focus, values and current route. New target not yet loaded: retain the prior locale and visible language selection; show a localized, nonblocking load status in the current locale. On success commit once; only then persist the new locale and announce. Do not prefetch the other six merely to make a future switch fast.
3. **Failure and recovery:** Model `ready`, `loading-target`, and `failed-target` with target and request generation; a stale resolution cannot apply after a newer selection, unmount or sign-in/scope change. A failed switch retains the previous valid catalog, `html.lang`, selector value and stored preference, with a current-language visible/live error and explicit Retry; no raw module/fetch error, silent fallback or misleading success. Explicit retry of the same failing module URL may be negatively cached by browsers: the recovery path must support a same-origin, cache-reloaded fetch of the emitted **canonical JSON asset URL** (Vite `?url` asset, no `eval`), validate its minimal string-record shape before use, and keep it page-local. Test that an initial failed request followed by an available asset actually recovers in bundled Chromium; never promise recovery based only on a mocked fulfilled import. Other app interactions are unaffected while a switch is pending. No automatic retry loop.
4. **Bootstrap failure:** The app and authenticated routes never mount without the selected catalog. An explicit, accessible, selected-language recovery screen with heading, explanatory text and Retry/Reload action uses a tiny static **build-derived subset** of existing `route.unavailable`, `route.loadFailed` and `route.reload` strings. Add a build/dev/test virtual module or equivalent build-time derivation that reads canonical JSON and emits just these recovery strings; do not hand-maintain a second seven-locale translation table or statically import whole JSON assets. Set `html.lang` to the selected locale; use a neutral content-free title and no protected content, navigation or API traffic. Change the static `index.html` title to neutral `MIA` so a non-English cold load never exposes an English route title before bootstrap. Only deliberate recovery reattempts loading; a failed repeat retains this state. If using Reload, it is user-initiated and must not replay any mutation. Recovery UI must use an established licensed alert variant, not invented blueprint markup.
5. **Availability and sizing:** All seven canonical JSON catalogs remain checked and loadable, regional variants preserve their strings, and the exact selector choices/negotiation stay unchanged. Entry/static closure contains **zero catalog assets**; exactly the active catalog (and any base or common dynamic dependency) loads on cold paint. Story 6.3's English-pinned proof measured 189,823 versus 256,554 gzip bytes, ~66.7 KB delta for the six non-active catalogs; this is an estimate, not acceptance of a smaller but semantically broken bundle. Count the new loader/recovery code, the active catalog, and any base/shared chunks against 260,000 for every locale. Emitted retry-only canonical JSON URLs must not be prefetched or fetched on normal boot. Enforce FFR-955 using the final build and investigate FFR-951/952 cold timing; no budget increase.

Static catalog strings and derived recovery copy are **public UI assets**, not authenticated content or secrets. In-memory catalog reuse and ordinary static-asset HTTP caching are allowed; the rules forbidding protected-data storage/cache and protected prefetch remain fully applicable to all API resources. No remote font/script, new origin, service worker, analytics, or runtime dependency.

## Risks and exclusions

- Vite 8 chunk factoring or preload might reattach catalogs to the entry, and regional imports may add a second base chunk. Browser module-map negative caching can prevent naive `import()` retry. Measure the actual manifest/network and test recovery in production Chromium; do not infer either result from source alone.
- Post-entry catalog fetch adds a round trip on cold cache under FFR-951/952. Measure and disclose regression. The small emergency subset/asset URL map also has entry cost. If any locale exceeds budget or misses the first-paint/performance requirement, stop and return measured evidence rather than pinning English, reducing catalogs, or raising the limit.
- Keep pre-React fragment stripping ahead of all optional loads, restricted stage isolation and the ordered protected mount. Never let an unresolved locale import or stale switch remount the app or leak an error body.
- No UI copy changes, locale negotiation change, new locale, profile preference API redesign, MFA expansion, unrelated route refactor, provider calls, remote scripts/fonts, or changes to FFR-956/upload progress. Existing 7.1 copy and state design remain in its separate spec.
